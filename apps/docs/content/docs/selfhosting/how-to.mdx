Chathouse is designed to be self-hosted. The entire stack — app, background worker, MySQL, and Redis — is defined in a single `compose.yaml` and can be running in under 5 minutes.

## Prerequisites

- A server (or local machine) with **Docker** and **Docker Compose** installed
- At least **1 GB of RAM** and **2 GB of disk space**
- An API key from at least one provider: [OpenAI](https://platform.openai.com/api-keys), [Anthropic](https://console.anthropic.com/settings/keys), or [Google](https://aistudio.google.com/app/apikey)

<Callout type="info">
  You don't need API keys to deploy — you'll add them through the web UI after your first login.
</Callout>

## Step 1: Clone the repository

```bash
git clone https://github.com/ChathouseHQ/chathouse.git
cd chathouse
```

## Step 2: Create your environment file

```bash
cp .env.example .env
```

## Step 3: Configure required variables

Open `.env` and set the two required variables:

**`SECRET_KEY_BASE`** — a master secret used to derive encryption keys. Generate one with:

```bash
openssl rand -base64 32
```

**`CLIENT_URL`** — the public URL where Chathouse will be accessible:

```bash
SECRET_KEY_BASE="paste-generated-value-here"
CLIENT_URL="https://chat.yourdomain.com"
```

If you're running locally, use `http://localhost:3000` (or whichever port you've configured).

<Callout type="warn">
  Both variables are required. `docker compose up` will refuse to start without them.
</Callout>

## Step 4: Start Chathouse

```bash
docker compose up -d
```

This builds and starts four containers:

| Container | Purpose                                   |
| --------- | ----------------------------------------- |
| `app`     | The web application (port 3000)           |
| `worker`  | Background job processor for AI responses |
| `mysql`   | MySQL 8 database                          |
| `redis`   | Redis for sessions and job queuing        |

First startup takes a few minutes while Docker builds the application image. Subsequent starts are near-instant.

## Step 5: Create your account

Open `http://your-server-ip:3000` in your browser and register your account.

<Callout type="info">
  Registration automatically closes after the first user signs up. Chathouse is designed as a
  single-user (or small team) application.
</Callout>

## Step 6: Connect your AI providers

Navigate to **Settings > Connections** and add API keys for the providers you want to use:

- **OpenAI** — get a key at [platform.openai.com/api-keys](https://platform.openai.com/api-keys)
- **Anthropic** — get a key at [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys)
- **Google Gemini** — get a key at [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)

Your API keys are encrypted at rest using a key derived from `SECRET_KEY_BASE` before being stored in the database.

## Updating

To update to the latest version:

```bash
cd chathouse
git pull
docker compose up -d --build
```

Your data is persisted in Docker volumes (`mysql_data`, `redis_data`, `uploads_data`) and survives rebuilds.

## Reverse proxy setup

In production, you'll want to put Chathouse behind a reverse proxy with TLS. Here's a minimal nginx config:

```nginx
server {
    listen 443 ssl http2;
    server_name chat.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

If you're using Caddy, it's even simpler:

```
chat.yourdomain.com {
    reverse_proxy 127.0.0.1:3000
}
```

Make sure `CLIENT_URL` in your `.env` matches the domain you've configured in the reverse proxy.

## Backups

The important data lives in two Docker volumes:

- **`mysql_data`** — all your chats, user data, and settings
- **`uploads_data`** — uploaded files

To back up the database:

```bash
docker compose exec mysql mysqldump -u chathouse -pchathouse chathouse > backup.sql
```

To restore:

```bash
docker compose exec -T mysql mysql -u chathouse -pchathouse chathouse < backup.sql
```

## Troubleshooting

### Containers won't start

Check the logs:

```bash
docker compose logs -f
```

The most common issue is a missing `SECRET_KEY_BASE` in your `.env` file.

### Database connection errors

Make sure the MySQL container is healthy before the app starts. The compose file handles this automatically with healthchecks, but if you're seeing connection errors, wait a moment and try again:

```bash
docker compose restart app worker
```

### Resetting everything

To wipe all data and start fresh:

```bash
docker compose down -v
docker compose up -d --build
```

<Callout type="warn">
  The `-v` flag deletes all Docker volumes, including your database and uploads. This is
  irreversible.
</Callout>
